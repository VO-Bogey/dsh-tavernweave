## 当前版本定位

当前版本命名为 **TavernWeave DSH `v0.3.0-beta.1`（第一版验证版）**。

这个命名表示：核心工具已经可以实际使用，但仍需要用真实 SillyTavern 角色卡完成第一轮验证；它不是最终稳定版。后续如果发现问题，会继续使用 `beta.2`、`beta.3` 递增；真实酒馆验收稳定后，再发布 `v0.3.0` 正式版。

## 1. 项目定位

这是基于 TavernWeave 原作者制卡思路、面向 DeepSeek Harness（DSH 0.1.2）的原生适配插件。

插件当前承担三类职责：

1. 在 DSH 会话 UI 中提供轻量制卡入口和 Soul 口令入口；
2. 在工作台中提供资料查阅、技能状态、角色卡结构盘点、组件级草稿编辑和版本记录；
3. 在宿主侧提供设置、资料库查询、卡片项目持久化和插件自身的安全更新检查。

模拟酒馆暂缓，不在插件中发送额外模型请求。真实 SillyTavern 验收仍是后续阶段，不应把静态检查当成真实酒馆验收。

## 2. 已完成内容

### DSH 0.1.2 原生适配

- 原生 preset：`presets/tavernweave-native/`
- 已接入 TavernWeave 20 个 Skill 与 DSH 原生工具链；验证脚本确认 20 个 Skill 均存在。
- 插件清单通过 `package.json` 的 `dsh.client.inject` 声明 renderer、sidebar、settings、conversation、input-trigger、session/workspace controller 等依赖。
- 入口可见性按 DSH 当前会话所属 Workspace 判断，不依赖启动 DSH 的终端当前目录。
- 白名单为空时不显示入口；白名单配置保存在用户目录的 DSH 插件数据目录中。

### 会话 UI

- 工具栏注册在 `conversation.input.dock`，位于输入框上方。
- 工具栏内容自适应宽度、右对齐输入框，不再占满整行。
- Soul 小图标悬停菜单向上弹出；口令可直接插入当前输入框。
- “从零写卡”“改造旧卡”按钮会把首轮制卡指令直接插入当前 DSH 输入框。
- “打开工坊”打开固定在页面上的工作台面板。

### 工作台

当前标签页：

- 口令速查：按原作者 newbie-guide 整理可复制口令；
- 技能状态：区分“目录可用”和“本会话实际加载”；
- 资料库：检索并打开本地 TavernWeave 指南；
- 制卡工作台：导入 JSON、结构盘点、项目阶段/版本记录、组件级草稿修改、导出 JSON；
- 更新：只检查和更新本插件仓库。

工作台已补充新用户引导：每个标签页有一句用途说明，制卡页有首用流程提示，资料库有角色卡/MVU/世界书/正则/开场快捷搜索。

### 资料库

资料库是原作者 TavernWeave 指南的只读索引，不是自动改卡的知识库。它用于：

- 查制卡流程、卡片格式、MVU、世界书、正则、开场和界面设计；
- 先理解实现边界，再把结论交给 DSH 或制卡工作台；
- 打开搜索结果阅读全文，不会自动修改角色卡。

全文读取接口已修复，前端正文显示在结果列表上方，并显示具体读取错误。

## 6. 当前已知限制

1. 尚未完成真实 SillyTavern 主机中的导入、发送、消息重渲染、MVU/世界书/正则和嵌入 UI 验收。
2. PNG 角色卡载荷解析尚未接入，制卡工作台当前直接读取 JSON；PNG 解析应放到后续打包阶段。
3. 工作台的组件编辑是实验性增量编辑，不能替代完整卡片流水线；不会覆盖原始卡文件。
4. 资料库当前是本地快照，随原作者更新由维护者同步，不提供用户直接拉取原作者仓库的按钮。
5. 插件仓库本地分支相对远端曾有分叉：当前 `main` 比 `origin/main` 超前多个本地提交，同时落后 1 个远端提交。后续更新逻辑必须继续保留 dirty/diverged 阻断，不能强行覆盖本地改动。
6. DSH 页面若使用旧 token 或旧页面缓存，可能出现认证失败或看不到新 UI；应从启动日志取得最新 URL 后刷新。

## 7. 下一阶段建议

当前版本已经进入“可制作第一张真实卡并用结果驱动迭代”的验证阶段。按优先级推进：

1. 在真实 DSH 会话中确认：白名单工作区显示/隐藏、工具栏位置、Soul 菜单插入、面板拖动和标签切换。
2. 完成 DSH 0.1.2 原生 preset 的新会话验收，确认 Agent Preset 选择后会话确实加载 TavernWeave 工坊能力。
3. 接入真实 SillyTavern 验收链：角色卡导入、首条消息、世界书、MVU、正则、Tavern Helper 和嵌入 UI。
4. 决定是否把资料库从“全文搜索”升级为“主题/阶段导航”，但保留只读和来源说明。
5. 若要支持 PNG 卡，单独设计解析、预览、哈希、回滚和打包边界，不要把它混入当前 JSON 盘点逻辑。

## 版本命名说明

本项目采用常见的语义化版本形式：`主版本.次版本.修订号-阶段.序号`。

- `0.x`：仍在快速开发，接口和流程可能调整；
- `beta`：主要功能已经可用，正在真实用户/真实环境验证；
- `beta.1`：第一轮验证版；发现问题后用 `beta.2`、`beta.3`；
- 去掉后缀的 `v0.3.0`：表示这一轮真实验证通过后的稳定版。

因此当前不要把它称为“最终版”，对外或对自己记录时称为“第一版验证版”即可。
